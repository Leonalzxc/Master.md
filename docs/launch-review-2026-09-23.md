# MASTER Moldova — ревью готовности к запуску

Дата: 23 сентября 2026. Вердикт: **публичный запуск пока No-Go**. Есть значительная часть интерфейса MVP, но не подтверждена безопасность данных и целостность основного сценария. Следующий этап — стабилизация, а не новый набор функций.

## Объём и ограничения

Сопоставлены доступная история чата, рабочие файлы Next.js, SQL-миграции, Server Actions, авторизация, Telegram, админка, формы, каталоги, SEO, платежные/юридические страницы, документы планирования, скрипты проверок и Telegram-боты разработки. Проверены локальная история Git, состояние main и список открытых PR на GitHub. Это статическое ревью и проверки сборки, не завершённый penetration test или юридическое заключение.

База production, её фактические GRANT/RLS/триггеры, настройки Twilio/Vercel, резервные копии и сценарии с двумя авторизованными пользователями не проверены. Риски SQL ниже подтверждены файлами; применимость к production нужно сверить с живой схемой. Эксплуатация уязвимостей на реальных данных не проводилась. Полная визуальная проверка мобильных экранов остаётся отдельной задачей.

## Что из предыдущих выводов чата нельзя переносить автоматически

- Для установленного Next.js 16.2.5 `proxy.ts` — правильная конвенция; локальная документация Next подтверждает переименование middleware → proxy. Прежний совет переименовать обратно был неверен.
- Типы прошли, но это не доказывает соответствие схемы БД и RLS. Много `as any` скрывает несовпадения; нужен types generation от проверенной схемы.
- Изменение maxAge не доказывает устранение всех разлогиниваний. В main оно есть, в рабочем дереве нет; нужно проверить refresh, удаление cookie при logout и копирование cookie в redirect-ветке.
- «Функции готовы» в старых ответах часто означало только существование файла. Неатомарные действия и неработающие admin UPDATE это подтверждают.
- README описывает старый static/localStorage прототип, roadmap и MASTER-PLAN — Next.js 14 и уже прошедшие даты. Их нельзя использовать как статус текущего продукта.
- Миграция `011_listings_city.sql` меняет RETURNS TABLE через CREATE OR REPLACE. PostgreSQL не допускает смену return type существующей функции таким способом; даже неиспользуемый legacy SQL мешает воспроизводимой установке. [Документация PostgreSQL](https://www.postgresql.org/docs/16/sql-createfunction.html).

## Границы продукта, которые нужно зафиксировать

1. В чате явно были требования «пока только Бельцы», обязательная точка карты и гибкие роли. Позже ассистенты расширили города и сделали карту необязательной; явного согласования этих изменений в доступной истории нет. Рекомендация для пилота: Бельцы, 2–3 категории, один аккаунт с обеими возможностями. Изменение scope — решение владельца до публичного позиционирования.
2. Сохранить Path A: Next.js + Supabase + Vercel. Переезд на NestJS/Redis сейчас не устраняет найденные ошибки и расширит объём работ.
3. Отложить PRO, подписки, чат, множество городов и SEO-конвейер. Довести один путь: OTP → анкета → заявка → отклик → выбор → контакт → завершение → отзыв.
4. Наличие юридической страницы не означает соответствия закону. На дату ревью CNPDCP указывает вступление Закона №195/2024 в силу 23.08.2026; старые шаблоны нужно пересмотреть с местным специалистом. [Материал CNPDCP](https://datepersonale.md/wp-content/uploads/2026/03/Legea-nr.1952024.pdf). Уточнить оператора данных, цели/основания, геоданные, документы, подрядчиков, трансграничные передачи и реальные процедуры удаления. Это перечень для проверки, не заключение о применимости всех требований.

Техническая основа безопасной Telegram-привязки: [deep links](https://core.telegram.org/bots/features#deep-linking) и [webhook secret_token](https://core.telegram.org/bots/api#setwebhook). Секрет webhook подтверждает отправителя события, но не владение UUID аккаунта.
