# MASTER Moldova — критерии допуска к запуску

Версия: 23.09.2026. Статус **No-Go**. Отметка требует evidence: commit/deployment ID, тест/лог, окружение, дата и проверивший. Наличие кнопки или страницы не закрывает пункт.

## G0. Единая версия и воспроизводимость

- [ ] Сохранены локальные изменения обоих деревьев; определён release branch от актуального main.
- [ ] 30 открытых PR разобраны; проверенные исправления учтены, дубли не объединены вслепую.
- [ ] Vercel project/root `web`/production branch/commit SHA/домен записаны и сверены.
- [ ] npm ci, typecheck, lint, i18n и production build проходят из чистого checkout.
- [ ] Public build/sitemap не требуют service-role ключа; реальные секреты только server-side.
- [ ] Quality script и CI не меняют исходники, не коммитят и не пушат.
- [ ] Dependency advisories разобраны; применимые critical/high исправлены либо компонент исключён с доказательством.
- [ ] Миграции воспроизводимы с нуля и на staging-копии схемы; production migration history сопоставлена; demo seed отделён.

## G1. Авторизация и приватность

- [ ] Guest/A/B/worker/blocked/admin проверены прямыми API-тестами.
- [ ] Нельзя выдать себе admin, verified, is_pro, credits, rating; нельзя создавать профиль чужого UUID.
- [ ] Публичные запросы не раскрывают phone, telegram_chat_id, документы и точную геоточку.
- [ ] Контакты доступны только сторонам выбранной работы; storage-документы приватны.
- [ ] Legacy RPC/таблицы/GRANT не обходят новое ограничение.
- [ ] Новые фото обрабатываются до Storage: EXIF/GPS/XMP удалены, размер и формат проверены; raw upload/overwrite/delete и чужие ссылки запрещены. Старые фото отдельно проверены на раскрытие адреса/метаданных.
- [ ] Blocked user не создаёт и не меняет заявки/отклики/отзывы.
- [ ] Возврат в профиль, refresh, истечение access token, logout, две вкладки, сбой сети проверены.
- [ ] Ошибка БД не вызывает upsert со сбросом роли и redirect loop.
- [ ] next принимает только безопасный внутренний путь, включая негативные тесты `//host` и обратного слэша.
- [ ] Telegram требует secret, одноразовый токен, TTL и private chat; чужой UUID и replay отклоняются.
- [ ] OTP rate limits/CAPTCHA или эквивалентная защита от злоупотреблений и SMS cost alerts проверены в провайдере.

## G2. Полный цикл заказа

- [ ] Регистрация с именем и продолжение после прерывания работают в RU/RO.
- [ ] Один аккаунт сохраняет возможности заказчика и мастера; admin не пользовательская роль-переключатель.
- [ ] Заявка сохраняется один раз, включая повтор после потерянного ответа и параллельную отправку; изменённый повтор открывает уже созданную заявку, не перезаписывает её. Прямой REST INSERT и подмена даты не обходят лимит.
- [ ] Сервер валидирует category/city/координаты/суммы/длины/фото/locale.
- [ ] GPS denied/timeout → ручная точка; нет ложных координат 0/0.
- [ ] Отклик и кредит атомарны: повтор/гонка/сбой не теряют баланс и не создают дубли.
- [ ] Нельзя откликнуться на собственную, заблокированную, отменённую или истёкшую заявку.
- [ ] Выбор привязан к правильному bid/job/worker; два выбора дают одного победителя.
- [ ] Отмена не перезаписывает уже выбранного исполнителя при гонке.
- [ ] Завершение, отзыв и рейтинг согласованы; нельзя оценить чужую/незавершённую работу через REST.
- [ ] Admin начисление/верификация действительно меняют строку и имеют audit log; повтор начисления безопасен.

## G3. UI, уведомления и доверие

- [ ] RU/RO smoke и Playwright: home, auth, account/profile, request, jobs, job detail, workers, review, error/404.
- [ ] 360/390/768/1440px, длинные данные, keyboard/Escape/focus, reduced-motion проверены визуально.
- [ ] Фото загружаются/удаляются согласованно с сохранением; частичный сбой не теряет ранее сохранённое портфолио. Переход шага/сохранение ждут загрузки, повторный клик не создаёт вторую отправку.
- [ ] Категории/города/фильтры/пагинация/счётчики/expiry достоверны; `page=abc` не ломает страницу.
- [ ] In-app notifications и Telegram проходят happy/retry/failure/replay; нет поддельного клиентского INSERT.
- [ ] Поддержка использует проверенные контакты, FAQ описывает только существующие функции.
- [ ] Badge «Проверен» точно описывает выполненную проверку; тестовые отзывы и цифры не выдаются за реальные.
- [ ] SITE_URL, canonical, hreflang, robots и sitemap согласованы; кабинеты и preview не индексируются.

## G4. Эксплуатация, право и пилот

- [ ] Регион хранения, подрядчики, цели/основания, retention и удаление сверены с действительностью.
- [ ] Пользователь может реализовать удаление/экспорт данных через реальный процесс; сроки не выдуманы.
- [ ] Юридические тексты проверены и утверждены владельцем; согласована применимость местных требований.
- [ ] Либо платежи выключены, либо есть реальные реквизиты, утверждённые цены/условия возврата, ledger и сверка оплаты.
- [ ] Жалобы на фейковых мастеров/заказчиков, споры и блокировки имеют владельца и рабочий процесс.
- [ ] Error monitoring ловит RSC digest/action errors с correlation ID без PII; alerts доходят ответственному.
- [ ] Backup восстановлен на staging; записаны фактические RPO/RTO. Frontend rollback и DB recovery проверены отдельно.
- [ ] Метрики публикации/отклика/выбора/завершения проверены, дубли событий исключены.
- [ ] Завершён пилот 7–14 дней, известны размер выборки и нерешённые проблемы.
- [ ] Нет открытых P0; оставшиеся P1 имеют владельца и дату, не затрагивают безопасность и основной путь.
- [ ] Founder принимает Go на конкретный SHA/deployment и подтверждённый scope; назначен ответственный на первые 7 дней.

Любой незакрытый пункт G0–G2 означает No-Go для публичного доступа. Для G3–G4 допускается только явно записанное исключение некритичной функции, которая отключена/удалена из публичных обещаний. Нельзя оформлять исключением доступ к чужим данным, потерю денег или нарушение целостности заказа.
