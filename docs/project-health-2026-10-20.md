# Проверка проекта 20.10.2026

## Подтверждённая причина ошибки

Production alias `master-md.vercel.app` указывает на
`dpl_CSeFo1Pg7SE3w63Fsc9L7L2N2q1p`, git SHA
`d9402674546cc0d6196e125feb6f5574e70d390e`, ветка main. PR #36 не объединён.
Vercel runtime-log за сутки содержит 500 на `/ru/request/new`, digest
`3541431670`: `Could not find the 'title' column of 'jobs' in the schema cache`.
Исходник production createJob действительно добавляет `title` в INSERT;
исходная SQL-схема этого столбца не содержит. Контрольный GET с `select=title`
и `limit=0` вернул 400/42703, без запроса пользовательских значений.

Для текущего production подготовлена отдельная ветка
`codex/fix-production-job-schema` от указанного SHA. Она не подменяет
большой release с ещё неприменёнными SQL. Hotfix убирает несуществующий столбец,
возвращает ожидаемые ошибки как значения, блокирует повторный клик и сохраняет
форму при ошибке. При неизвестном результате сети предлагает проверить кабинет
перед повтором: атомарная idempotency доступна только после большого SQL rollout.

## Что не проверено и что блокирует полный выпуск

1. Нужен действующий пароль PostgreSQL в ignored `web/.env.db.local`.
   Временный CA-файл исчез; официальный CA восстановлен в постоянный каталог
   `Documents/Codex/certificates`, TLS/hostname verification не отключалась.
   Затем — согласованная резервная копия и проверка восстановления до миграций.
2. Применить девять согласованных migrations к изолированной копии, проверить
   старые данные, RLS/GRANT и Storage; затем согласованно выпустить frontend.
   Просто продвинуть PR #36 в production без SQL нельзя: отсутствуют RPC.
3. Пройти двумя настоящими аккаунтами SMS → анкета → фото/точка → публикация
   → отклик → выбор → закрытые контакты → завершение → отзыв; проверить
   logout/refresh/две вкладки/обрывы сети. SMS и внешние сообщения в проверках
   не отправлялись. Тестовые заявки в production не создавались.
4. Проверить лимиты/антибот и расходы SMS-провайдера, конфигурацию Telegram
   secret и одноразовых ссылок. Реальная доставка остаётся отдельной проверкой.
5. Утвердить оператора, retention и обработку запросов об удалении/экспорте;
   провести аудит старых публичных фото и приватных verification-docs после backup.
