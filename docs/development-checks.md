# Проверки перед commit и PR

Приложение находится в `web/`. CI использует Node 22 из `web/.nvmrc` и
`npm ci` с закоммиченным lock-файлом. Локальная подготовка:

```sh
cd web
nvm use
npm ci
npm run quality
```

`quality` последовательно запускает ESLint, сверку ключей RU/RO, проверку
границ Supabase client/server, тесты PostgreSQL, production build и TypeScript.
Сборка предшествует отдельной проверке типов, чтобы создать типы маршрутов
на чистом checkout. Первая ошибка останавливает выполнение.

Скрипт не исправляет исходники, не выполняет SQL в Supabase, не создаёт
commit и не делает push. Сборка и TypeScript могут создавать только свои
обычные кеши. Форматирование и автоисправления запускаются отдельно:
`npm run format` и `npm run lint:fix`. Полное форматирование старого кода
не включено в обязательный gate, чтобы не смешивать его с исправлениями.

## Автоматические проверки

Workflow `.github/workflows/quality.yml` запускается на PR в любую ветку и
на push в `main`. Использует права `contents: read`, не сохраняет GitHub
credentials в checkout и не получает production-секреты.

Для сборки заданы фиктивные Supabase URL/key. Она не должна обращаться к
рабочей базе. Внешняя сеть нужна для установки npm-пакетов и загрузки
шрифтов Next.js. Чтобы воспроизвести CI локально, используйте чистый
checkout без `.env.local` и переменные из workflow.

`npm test` запускает 10 тестов доступа в изолированной PGlite/PostgreSQL:
публичный каталог, запрет чтения контактов, личный профиль, доступ выбранного
мастера, блокировки, смену роли, регистрацию, служебные уведомления,
повторный запуск миграции и создание заявки через реальную server action.
Тесты не читают `.env` и не отправляют SMS/Telegram.

## Границы этапа

Успешный gate не означает, что миграции применены в production или что
пройдено браузерное тестирование OTP/платежей. Применение миграции приватности
требует согласованного выпуска кода: см. `profile-privacy-rollout.md`.

Ветка разработки расходится с `main`; сведение версий и проверка открытых
PR остаются отдельным этапом. Проверки зависимостей, атомарность откликов
и безопасная привязка Telegram остаются в `launch-plan.md`.

Удалена устаревшая утилита `update-package-json.cjs`: она возвращала
несуществующий в Next 16 `next lint` и ссылалась на отсутствующий Husky.
Источник истины для команд — `web/package.json`.
